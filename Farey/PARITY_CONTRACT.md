# Coefficient-cone parity contract

A shared, checkable definition of "the same behavior" for the browser, native and any other implementation (for example a separately owned Lean version). It compares mathematical results and operations, with declared platform adaptations, not pixel identity.

## Exact data: `parity/fixtures.json`

`parity/generate-fixtures.mjs` computes every expected value with the browser's own modules (`WebXR/starscape-core.js`, `lattice.js`, `pair-plane.js`), so nothing in the fixture file is hand-typed. Regenerate from `Farey/` with `node parity/generate-fixtures.mjs > parity/fixtures.json`. Native FareyCore is checked against the same file by `ParityContractTests`. Another implementation should load the JSON and assert the same fields.

**Exact versus approximate.** Integers, kinds, equations and every `…Exact` field are exact; `…Approx` fields are IEEE doubles for tolerance checks only.

- `upperRootExact` gives the positive representative's upper root as (realNumerator + i·√imaginaryRadicand)/denominator, with denominator = 2a > 0. For example, (1,0,1) and (2,0,2) give different but equal representations of i.
- `realRootsExact` and a plane's `endpointsExact` tag each root as `infinity`, a `rational` p/q in lowest terms, or a `quadratic` (numerator + sign·√radicand)/denominator, unreduced, with branch sign −1 then +1.
- `realRoots` and `endpoints` are human-readable labels only, not something to parse.

The fixtures are regression contracts, generated by the browser modules and checked against native code; they are not kernel-verified theorems.

The fixture file contains:

- **Basis:**
  - display coordinates (X,Y,Z) = (−b, a+c, c−a);
  - Δ = b²−4ac = X²+Z²−Y²;
  - the ball b²+2a²+2c² ≤ R², zero excluded;
  - Y ≡ Z (mod 2).

  Data, kinds, planes and labels are exact; drawn positions are floating point.
- **Census for R4, 6, 8, 10, 12:** 128, 480, 1060, 2100 and 3608 triples, each split into upper, lower, null and exterior. The browser's R96 (1,852,484 points) is a browser-only capacity, not a parity target; native caps at R12.
- **Ten named points**, each with kind, Δ, vector, polynomial, primitivity, upper root, exact real roots and ball membership per radius. Among them:
  - (1,−1,2) and its sign partner (−1,1,−2): the same roots, opposite vectors, with the actual signed triple kept.
  - (1,0,1) and (2,0,2): visible R6 multiples with the same root i.
  - (2,−2,4): hidden at R6 and visible from R8.
  - (1,−2,1): a double finite root 1.
  - (0,0,1): no finite root, with a double projective root ∞.
  - (0,1,0): a finite root 0 and a root at ∞.
  - (1,0,−2): roots ±√2.
- **Three planes:**
  - the pair (1,0,1)/(1,1,1), with normal (1,0,−1), `2a −2c = 0`, endpoints −1 and 1;
  - the normal (0,1,0), giving `b = 0` with endpoints 0 and ∞;
  - the normal (1,0,−2), giving `4a −2c = 0` with endpoints ±√2.

  The first two each have 22 displayed interior triples at R6 (11 upper and 11 lower, counting multiples and sign partners, not distinct roots); the third has 10.
- **Rejections, with shared codes:**
  - a multiple or sign partner of the selection gives `sameDirection`;
  - a null or exterior second point gives `notInterior`;
  - a null or interior normal gives `notExterior`;
  - zero gives `zero`.

## Silent walkthrough checkpoints

Record app-only, without audio. Each receipt should note the version, commit, fixture IDs, input mechanism, screenshot or video hashes, any console errors, and what was not verified.

1. **Fresh R6 overview:** 480 points, (1,−1,2) selected, projection off.
2. **Hover:** (1,0,1) shows `x² + 1`, then (2,0,2) shows `2x² + 2` (browser only; the native gap is stated).
3. **Select a multiple:** select (2,0,2); same root as (1,0,1), different depth.
4. **Pair:** select (1,0,1), pair (1,1,1); the plane is `2a −2c = 0`, endpoints −1 and 1, with 22 interior triples.
5. **Origin:** facing the upper nappe, then the lower nappe, with the pair and plane kept; then return to Overview.
6. **Reset:** defaults are restored and the pair is cleared.
7. **Density:** R12 (3,608 points) on both platforms; R96 in the browser only.
8. **Lifecycle:** exit and re-entry, which returns to Overview with state preserved; controller analogs only where actually tested.

Current evidence boundaries:

- Browser 0.14.0: foreground immersive frames are unverified.
- Native: tested in visionOS Simulator only; the physical headset is untested.
